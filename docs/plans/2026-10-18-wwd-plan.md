### WWD-3 — manifest, queue, local jobs (`_doxhaf` server, A5 client)
- **3a** (A5) `internal/wwd/manifest`: parse, validate, the task definition hash; the purdex manifest.
- **3b** (`_doxhaf`) queue store and state machine per spec §4.2: claim with `claim_id`, `start`, `heartbeat`,
  `release` (reclaim / infra), `result` (idempotent per claim) and `log`, relative leases, origin-restart grace,
  supersede (queued and running interruptible, `superseded_by` for non-interruptible), expiry, retention. `locks` are
  stored and listed only — the worker enforces them on the host that runs the job (spec §4.1, §5); the gate's manual
  rank is not carried over (spec §16). Split: 3b-1 the `JobSubmission` wire type and `interruptible` /
  `queue_timeout_s` / `adhoc` on the job; 3b-2 store, migration, submit / list / cancel / supersede / expiry /
  retention; 3b-3 claim / start / heartbeat / release / result / log, leases, restart grace; 3b-4 HTTP routes (socket
  and peer handlers). Tests: transition table; concurrent claims under `-race`; stale
  `claim_id` on heartbeat / result / log / release / snapshot → 409 with no change; lease lapse with a fake clock and a
  skewed worker clock; origin restart grace; idempotent result; TCP `POST /v1/jobs` → rejected; ad-hoc jobs absent from
  peer listings and a peer's claim of one → 409.
- **3c** (A5) `pdx test` / `pdx jobs` / `pdx wwd`, exit codes (spec §8.1), waiting on the socket's events.
- **3d** (A5) local execution: workspace from the snapshot, clean environment, summary parsers.
- **3e** (A5) the local fast lane on the gate's light-slot code.
- **3f** (A5) completion notice through the Purdex daemon. Tests: one notice per job for succeeded, failed, cancelled,
  superseded, expired, lost and cache hit; the caller exited while the session lives → still one notice.
- Acceptance: purdex's merge-tier tests run end to end with `pdx test` on mlab; the gate still serves the rest.

## Review, release, deploy

- Every PR except bumps and pure moves: codex R1 + R2 (attack → critic), `--model gpt-5.6-sol`, effort low; prompts
  say "do not run go test ./... or full vitest; at most the affected package; do not find/rg above the repo".
- New `exec.Command` → `./internal/execstat/` alone (no `-run`). Mod changes → `go test ./cmd/pdx/...`.
- Members report ready and wait for the lead's release. Deploy at each checkpoint (bump PR, both Purdex hosts, wwd on
  all four); relays_active = 0 checked before restart and before `pdx setup`.
