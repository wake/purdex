## Phase detail (PRs)

`make lint`; SPA `vitest related` + `tsc`), run on air26 through the lead's assist scripts until WWD-4 is accepted, then
through `pdx test` itself.

### WWD-1 — wwd skeleton and facts (A4)
- **1a** `cmd/wwd` skeleton: config, HTTP on 7871 (tailnet + 127.0.0.1), socket, pool token, `/v1/info`; Makefile
  targets for darwin/arm64, darwin/amd64, linux/amd64. Tests: the new packages; a cross-build check.
- **1b** macOS facts: reuse `internal/hostmem`; libproc for top processes and ownership; tool versions; 5 s ring and 1 m

- **1c** Linux facts: PSI, `/proc` readers, the M-L mapping. Tests: fixtures from M-L's recordings.
- **1d** derived `zone` / `headroom` / `sessions_room` (one package, used by everyone later); `/v1/facts`,

  cases), headroom table, pool with fake peers.
- **1e** install: `pdx setup` (LaunchAgent) on mlab and air26; an install script and unit for mserv (systemd) and air19
  (LaunchAgent). Acceptance script `wwd-accept-1.sh`.
- Acceptance: all four hosts report facts; wwd idle CPU < 1%, RSS < 50 MB measured on each.

## Review, release, deploy

- Every PR except bumps and pure moves: codex R1 + R2 (attack → critic), `--model gpt-5.6-sol`, effort low; prompts say
  "do not run go test ./... or full vitest; at most the affected package; do not find/rg above the repo".
- New `exec.Command` → `./internal/execstat/` alone (no `-run`). Mod changes → `go test ./cmd/pdx/...`.
- Members report ready and wait for the lead's release. Deploy at each checkpoint (bump PR, both Purdex hosts, wwd on all
  four); relays_active = 0 checked before restart and before `pdx setup`.
