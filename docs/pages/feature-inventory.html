01新方向：待討論需求（2026-09-18 提出）

這兩項還沒討論定案，但會決定下面很多列的處置，所以放最前面。

① Profile 機制 — 取代 Home 按鈕，成為整份狀態的同步單位

動機：a19 與 a26 兩台同步並用，兩邊 Purdex 的 tab 經常混淆、腦袋無法快速切換 → 需要的是同步架構
  1. a. Client 增加 profile 機制；原本完全沒在用的 Home 按鈕改為切換 profile。
  2. b. 一個 profile 記錄完整整份 purdex 資料：workspace ＋ tab ＋ session ＋ cwd ＋ hosts ＋ 所有設定參數。
  3. c. 不同 client 的同一個 profile 半即時同步（目標 1 秒內）；衝突排 event queue、先進先出。
  4. d. profile 可以複製。
已查證：daemon → client 的 push 有 —— /ws/host-events（internal/core/events.go 的 EventsBroadcaster，同一台 host 的所有 client 都收到）。但 payload 目前是 (session, eventType, value) 這種 session／agent 導向的字串，profile 同步要在同一條通道加 event type，不必另建傳輸層。
範圍界線：tab rebuild 保留，整合成 profile 的形狀跟著 tab 走（cwd 本來就跟著 tab）；直接被取代的是 snapshot／device-state 那條線（見下方 併入 Profile 各列）。
待討論：profile 的 SOT 放哪台 daemon（沿用 devHostId 還是每個 profile 綁一台）／「所有設定參數」是否含 host token 這類機密／1 秒內的延遲預算與 event queue 語意（誰先進、client 端要不要樂觀套用）／與現有 Sync 模組的關係（三台都 0 筆，建議直接拔）。

② Project icon — 用 cwd 比對，命中就換掉 tab 上的 host 圖示

底色仍舊是 host color，只換圖示那一層
  1. 提供 project icon 設定，用 cwd 資訊比對；有 match 時該 tab 的 host icon 改用 project icon 顯示。
銜接點：alpha.362 的 host badge（HostBadge.tsx ＋ useTabHostBadge.ts，每台 host 自選 Phosphor 圖示＋淡底色）正好是同一個元件的兩層資料來源——底色留給 host、圖示改吃 project，不是新元件。Host › Projects（alpha.359）已經有 name／slug／path 的 CRUD 存在 daemon（host_config.db，mlab 上已有 projects rev 1），可以直接當 project 定義來源。
待討論：cwd 比對規則（前綴？最長匹配？多層專案）／icon 存在 daemon 的 projects 還是 client 端／圖示選擇器沿用 CommandIconPicker 那套 Phosphor search。

05收束建議（草案）

🔁 A. 併入 Profile（方向已定，範圍待討論）

  • 各電腦狀態備份 device-state（SPA 1762 行 ＋ daemon 460 行 ＋ device_state.db）：完整取代／合併／刪除那套 UI，正是 profile 要做的事，但只同步「結構」且要手動按
  • 工作區快照 snapshot（1576 行，存 localStorage）：擷取／還原全部／還原版面／undo 都被 profile 的持續同步取代
  • Host › Snapshots 頁：device 區塊與 tmux 區塊都跟著重整；只有「rebuild 紀錄」要留
  • tab rebuild ＋ resume 範本（2975 行）＝保留，改成跟著 profile 的 tab 走（cwd／agent／resume 本來就掛在 tab 上）
  • 順帶決定 Sync 模組的去留：三台 0 筆、file-provider 是死碼、6 條路由無人呼叫 → 建議直接拔，profile 就是新的同步架構

🧹 B. 直接清掉（零風險）

  • SPA 死碼共約 1.3k 行（零非測試 import）：SessionPanel 132 ／ SessionPicker 67 ／ NewPanePage 33 ／ useGlobalSettingsStore 74 ／ useIsMobile 7 ／ tab-state 11 ／ open-clustered-tab 27 ／ agent-ws-dispatch 4 ／ sync/providers/file-provider 182

  • Dashboard 模組（12 行）：唯一能開它的 NewPanePage 本身就是死碼
  • Files 的 session 檔案樹（14 行，寫著「尚未實作」）；介面設定的 Pane／Sidebar 兩個分頁（() => null ＋ coming soon）
  • 桌面 App 頁的 3 個瀏覽器欄位：uncontrolled、沒有 onChange、沒有 store，實際值寫死在 browser-view-manager.ts
  • ModuleConfigSection ＋ workspaceConfig／globalConfig：沒有模組宣告，永遠 render null，registry 還在印 deprecation 警告
  • daemon 死路由／死鍵：/api/ready、/api/execution/{id}、/api/dispatch/reclaim（P-D.1 已移除）、codexbroker 2 條、sync group／pair 6 條、allowed_paths、[features]

  • 入口要一起收：分頁右鍵「切換 Stream」、狀態列 view-mode 選單、/t/:id/stream 路由、通知點擊目前預設開 stream 模式、stream.presets

  • alpha.360 已註記：stream 模式之後會以 Nexen 模式回歸，Session Launcher 已經不再提供 stream 選項

❓ D. 要你決定

  • 4 區 sidebar 版面（737 行，04-18 後沒動）：四個區塊只註冊 2 個 view，其中一個還是空殼。補 view 還是縮成單一側欄
  • agent trace（trace_chains／steps）：兩台都頂到 10000 chain 上限、mlab 佔 198 MB，但 alpha.361 把讀取端整個刪了，現在只寫不讀。Lights Phase 5「Dev Inspector」從未實作 → 要停寫、要縮上限，還是要把讀者做回來
  • codexbroker（4903 行 Go）：無 UI、只能 curl，P3 自動觸發從未實作
  • 內嵌瀏覽器（SPA 430 ＋ Electron 640 行，只有桌面版）
  • 自訂主題編輯器（263）／自訂語系編輯器（242）：內建 4 主題與 en／zh-TW 保留
  • 分頁首頁 layout 編輯器（417）：3／2 欄 profile 預設都關，只有 1 欄強制啟用
  • History 頁（158，06-30）：只顯示 raw kind 字串
  • 效能監控（688）：pane kind 沒有任何入口，只能從設定進 → 補 pane 入口或收掉

🔀 E. 設定面整併（功能不刪，只換位置）

  • 連結偵測：終端機頁放「純檔名」1 項，編輯器頁放「絕對／tilde／相對」3 項，但四者同一個 store、同一個消費端（terminal-link/register.ts）、都只作用在終端 → 全部集中到終端機頁
  • 通知設定：store 有被 useNotificationDispatcher 讀、也進了 sync，但四個 setter 零呼叫端，且 settings.agent.* 與 settings.section.agent 的 en／zh-TW 字串都還在 → 一個 Agent 設定頁被拆掉後留下的殘骸，要接回來
  • 同一 scope 兩套存法：Workspace 的「專案路徑」存 useWorkspaceStore.moduleConfig，Home Path 存 useWorkspaceSettingsStore；同一頁兩個持久化 key
  • 「快照」語意重疊：Host › Snapshots（工作區／裝置）vs 設定 › 同步 › 歷史（sync bundle）
  • 三套 host 選擇器：同步主機、開發主機（也兼 device-state 目標與 snapshot 區塊的顯示條件）、resume 範本測試對象
  • 終端機頁偏長：host badge 有側欄／上方分頁兩組各 7 個旋鈕（共 14 項）擠在同一頁
  • 小問題：外觀頁兩個都叫「自訂」／編輯器頁 6 個布林有 4 個是原生 checkbox／WorkspaceSettingsPage 的「Workspace not found」與「Danger Zone」硬編英文／分頁右鍵的「加入 … tab 成為 pane」是全 app 唯一沒 i18n 的選單字串／tabNameTooltipMode 與 4 個 linkDetect* 沒進同步／setTerminalRenderer 等 store action 已無生產呼叫端
