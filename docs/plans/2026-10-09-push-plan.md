# Phone push notifications (APNs) — plan

Spec: `docs/specs/2026-10-09-push-spec.md`. Four PRs (PU-1 … PU-4), in order; the iOS PR runs in parallel in
purdex-ios against spec §4/§6/§8.

Rules for every task:
- TDD: the failing test first, then the code. One commit per task. Mutation check before asking for release: break the
  rule each test guards, see it red, restore.
- Tests that touch tmux: `-L <label>` and `unset TMUX`, never a bare `kill-server`.
- mlab resources: only the affected packages (`go test -race ./internal/module/push/...` etc.); `make lint`; a full
  `go test ./...` only before merge with the slot from purdex-1f.
- Secrets: never print `config.env`, the `.p8`, a JWT or a full device token — not in tests, logs, PR text or
  messages. Tests use a key generated in the test (`ecdsa.GenerateKey(elliptic.P256(), rand.Reader)` → PKCS#8 PEM
  in `t.TempDir()`).
- No work under another module's lock: anything a team or agent hub delivers is handled on the push module's own
  goroutines; hub publishes are non-blocking channel sends.
- Review per PR: codex R1 + R2 (attack → critic). Release by the lead.

## PU-1 daemon: module, config, store, devices API, conditional `push.v1`

1. **Config.** `internal/config`: `PushConfig{APNsDir string}` under `toml:"push"` / `json:"push"`, zero value =
   off, included in the deep copy. Boot-only (spec §3): not added to `PUT /api/config`'s request type. Tests: absent
   section → off; `apns_dir = "~/x"` round-trips; copy is deep; a `PUT /api/config` body carrying `push` leaves the
   stored `[push]` unchanged.
2. **Key loader.** New package `internal/push/apnskey`: `Load(dir string) (Key, error)` opens `dir` with
   `os.OpenRoot` and reads `config.env` and the key file **through the root** (spec §3): only `APNS_KEY_ID`,
   `APNS_TEAM_ID`, `APNS_KEY_FILE`; `KEY=value` lines, `#` comments, optional quotes; PKCS#8 → `*ecdsa.PrivateKey`
   on P-256. `Key.String()` returns `apnskey(<key id>)`; no other formatting exposes it. Tests: happy path; missing
   key / file; wrong curve; RSA key; `APNS_KEY_FILE` absolute, with `..`, and a symlink that points outside → error;
   comments / quotes; error texts never contain file content.
3. **Store.** `internal/module/push/store.go`: `push.db` in the data dir (pattern of
   `internal/module/hostconfig/store.go`), the table of spec §4.4 (with `device_id`), `Upsert`, `DeleteByID`,
   `List`, `MarkSent`, `MarkError`. Tests with `:memory:`.
4. **Validation + wire types.** `internal/push/wire.go`: `DeviceRequest`, `Prefs`, `AgentPrefs`, `DeviceView`
   (masked token + `device_id`), `PresenceRequest` / `PresenceSession{Code, Name}` (PU-3 uses them), `DeviceID(token)`
   (first 16 hex of SHA-256 of the lowercased token). `Validate()` per spec §4.1. Table tests for each rule; masking
   `ab12cd34…ef90`; `DeviceID` stable and lowercase-insensitive.
5. **Module + routes.** `internal/module/push`: `Name() "push"`, Init loads the key (Init error → module fails to
   init, logged without secrets), opens the store, loads the cache; routes `POST /api/push/devices`
   (`http.MaxBytesReader` 64 KiB → 413), `DELETE /api/push/devices/{device_id}`, `GET /api/push/devices`. Cache and DB
   written together under one mutex (DB first, cache after success). Handler tests: upsert twice → one row, fields
   replaced, same `device_id`; delete by id idempotent 204; GET masks; 400 cases; 413; **no response body or log line
   on any path contains the full token** (capture the logger in the test).
6. **Registration + capability.** `cmd/pdx/main.go` `registerServeModules`: add the module only when
   `Cfg.Push.APNsDir != ""` (like `[nex]`). `internal/core/info_handler.go`: append `"push.v1"` after the static list
   when `c.Mounted("push")`; keep the static list untouched (comment: the one conditional capability). Tests: info
   without the module has no `push.v1`; with it mounted it does; the static list is unchanged.

## PU-2 daemon: APNs client, sender, approval trigger

1. **JWT.** `internal/push/apns/jwt.go`: `Signer{key, keyID, teamID, now}` → `Token()` returns the cached JWT while
   younger than 40 min, else signs a new one (ES256, header `{alg,kid}`, claims `{iss,iat}`; signature = r‖s, 32
   bytes each, base64url without padding). `Invalidate()`. Tests: verify the signature with the public key; reuse
   within 40 min; new token after 40 min (fake clock); invalidate forces a new one.
2. **Client.** `internal/push/apns/client.go`: `Send(ctx, env, token, headers, payload) Result` against a base URL per
   env (production / sandbox constants; tests inject an `httptest.NewUnstartedServer` with `EnableHTTP2 = true` +
   `StartTLS` and its client). Result classes per spec §7 from status + APNs `reason`. 10 s timeout. Tests: every
   class, the request headers (`authorization: bearer …`, topic, push type, priority, expiration, collapse id),
   HTTP/2 used (`r.ProtoMajor == 2`).
3. **Payload + strings.** `internal/push/content.go`: builders for the four triggers of spec §6 and the §5.3 body
   normaliser (Markdown markers, whitespace, 240-rune cut, title 120 runes) with zh-TW / en tables; size check
   ≤ 4096 bytes (if over, cut the body further). Tests: each trigger in both locales; normaliser cases (bold, code,
   headings, quotes, bullets, links, CJK cut at a rune boundary); size cap; `WorkerTerminated` and unknown events
   return no content (deliberate, spec §5.3).
4. **Sender.** `internal/module/push/sender.go`: one goroutine, queue 256, `Enqueue(job)` non-blocking (drop +
   counter + rate-limited log). A job carries its recipients (device ids) and payload. Per recipient: send; on ok
   `MarkSent`; on remove → store delete + cache; on JWT error → `Invalidate` + one retry; on retry-later → one retry
   after 2 s (fake sleeper in tests); else `MarkError` with the reason. Logs carry the masked token only. Stops on
   module Stop (in-flight request cancelled). Tests with the fake APNs: each path; a full queue never blocks
   `Enqueue`; Stop returns; captured logs never contain the full token or the JWT.
5. **Team feed.** `internal/team`: `ApprovalEventsKey` + interface
   `ApprovalEvents{ SubscribeApprovals(fn func(op string, a Approval)) (open []Approval, unsubscribe func()) }`.
   `internal/module/team`: a hub like `turnEndHub` (per-subscriber bounded channel + goroutine that runs `fn`,
   non-blocking publish, drops counted). `SubscribeApprovals` reads the open rows and registers the subscriber
   **under `eventMu`** (so no event falls between); `broadcast` publishes after the host event with a non-blocking
   send (comment why that is allowed under `eventMu`). Register in the Registry at Init. Tests: opened / closed reach
   a subscriber; a callback that blocks forever does not slow `broadcast` (time-bound); the snapshot + subscribe has
   no gap (open / close rows concurrently with `SubscribeApprovals`; every row ends in the subscriber's view in its
   final state); unsubscribe stops delivery.
6. **Approval trigger.** push module `Dependencies()` adds `team`; at Start it subscribes (keeps `open` for PU-3).
   On `opened`: kinds of spec §5.1 (hook_ask only when `terminal_only` is false); the job's recipients are all
   devices; R6 check is a no-op until PU-3 (an interface with an always-false fake). Tests through the real team
   paths (team module in-process): a lead created with unattended off pushes; `createApprovedLead` (unattended on) and
   `beginApproved` push nothing; an answerable `hook_ask` from `handleAskBegin` pushes; a terminal-only row from
   `openTerminalOnly` reaches the feed as `opened` and is not pushed; `hook_permission`, `adopt` and `closed` not
   pushed.

Acceptance after PU-2 (lead + iOS, real device): lead request with unattended off pushes; with it on, none; an
AskUserQuestion in a mod session pushes and the tap lands on the question.

## PU-3 daemon: agent hub, gate, presence

1. **Agent notify hub.** `internal/module/agent/notify_hub.go` like `turn_end_hub.go`: `SubscribeNotify(fn
   func(NotifyEvent))` with `NotifyEvent{SessionCode, SessionName, SessionID, Event agentpkg.NormalizedEvent}`;
   published from the single `hook` broadcast point in `hookemitter.go`, tmux sessions only, never for
   subscribe-time replays (`Snapshot`). Add `SubscribeNotify` to the narrow interface the push module gets from the
   Registry. Tests: a hook frame, a mod-stream frame (`modworker.go`) and a sweep / probe frame each publish once; a
   hook answered 500 before the emit publishes nothing; a replay is not published; a non-tmux session is not
   published; a stuck subscriber does not slow the emitter.
2. **Presence.** `internal/module/push/presence.go`: in-memory map `client_id → {active, sessions, expires}`,
   `PUT /api/push/presence` per spec §5.4 (16 KiB body cap → 413; client id 1–64 printable; sessions ≤ 200 with
   code + name; ttl 1000–60000 ms; ≤ 64 entries, expired dropped on every PUT, the soonest-expiring replaced when
   full; 204). `ShowsCode(code)`, `ShowsName(name)`. Tests: shows / expires (fake clock) / inactive does not count / a
   second PUT replaces the first / 65th client replaces the soonest-expiring / 413 / validation.
3. **Gate.** `internal/module/push/gate.go`, staged per spec §5.2: event stage (0 freshness per session code by
   `BroadcastTs`, 1–3, 4 presence), device stage (5–6) returning the recipients, send stage (7 debounce — once per
   event, only when recipients exist —, 8, 9). The debounce is the Mac's (trailing-edge sliding 60 s, 1000 keys,
   oldest evicted). Port the Mac's `shouldNotify` cases into a Go table and add rows for: freshness (same /
   older `BroadcastTs` not pushed), tabs / `notify_without_tab`, presence, **two eligible devices get the same error
   event and the next identical error within 60 s reaches neither**, no recipients → no debounce entry.
4. **Open hook_ask set.** Built from `SubscribeApprovals`' `open` snapshot and kept by its events (opened → add,
   closed → remove), plus "opened in the last 10 s" per session, keyed by origin `session_id` and the tmux session
   name of `origin.tmux` (part before the first `:`). Tests: add / remove; restart = a new subscription rebuilds from
   the snapshot; the 10 s window.
5. **Agent trigger.** At Start subscribe to the notify hub. Per event: event stage; device stage; a `waiting` event
   is held 2 s (timer on the push module's goroutine, not the hub's) before the send stage; build the agent payload
   (spec §6, collapse id `agent-<code>`); enqueue. The approval trigger now applies R6 by the origin's tmux name
   (`ShowsName`; no tmux → never suppressed). Tests end to end with fake APNs: Stop in a tab → push; not in tabs →
   none; with `notify_without_tab` → push; presence → none; expired presence → push; **a `waiting` frame that arrives
   before its `hook_ask` `opened` (within 2 s) → only the hook_ask push**; a `waiting` frame with no hook_ask → pushed
   after 2 s; approval from a session a present Mac shows → none; approval whose origin has no tmux → pushed.

Acceptance after PU-3 + PU-4 (real device): the agent rows of spec §10.

## PU-4 SPA: Mac presence reporter

1. **Activity tracker.** `spa/src/lib/presence/activity.ts`: last input time from `keydown`, `pointerdown`,
   `pointermove` (throttled), `wheel` on the window; `isActive(now)` = `document.hasFocus()` and input within 120 s.
   Tests with fake timers and dispatched events.
2. **Visible sessions per host.** A selector over the active tab's panes (every pane, as `isAgentVisibleInActiveTab`)
   → `Record<hostId, {code, name}[]>` (name from the sessions store). Tests: split tab, non-session panes ignored, no
   active tab → empty.
3. **Reporter.** `spa/src/hooks/usePushPresence.ts`, mounted once in `App.tsx`: for every connected host whose
   `/api/info` announced `push.v1`, PUT `/api/push/presence` with `{client_id: getClientId() + ':' + windowId,
   active, sessions, ttl_ms: 45000}` on change (debounced 300 ms) and every 20 s while active; one `active:false` when
   it stops being active; nothing to hosts without `push.v1`. Failures are ignored (next tick retries). Tests: sends on
   focus / tab switch; heartbeat; `active:false` once; skips hosts without the capability; per-host session lists.
4. Tab-hosted state checklist: not applicable (no tab-hosted component).
