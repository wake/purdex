## 2. Bus events full list

**Source**: `packages/opencode/src/**` — 48 distinct event keys（含 41 個 `BusEvent.define` + 7 個 `SyncEvent.define` runtime bus-register；`global.disposed` 重複 define 但 last-write-wins）。

**Bus abstraction**:
- Define API: `BusEvent.define(type: string, schema)` (`bus/bus-event.ts:10`)
- Publish APIs: 3 mechanisms (重要 — 非全部都進 typed `Bus.subscribe(def, cb)`):
  1. `bus.publish(def, props)` — typed Bus → 進 typed pubsub + SSE
  2. `GlobalBus.emit("event", { payload })` — bypasses typed Bus → **typed `Bus.subscribe(def, cb)` 收不到，但 `subscribeAll()` 收得到**
  3. `PubSub.publish(wildcard, ...)` (僅 finalizer use) — wildcard only
- Subscribe (Purdex 用): `bus.subscribeAll()` (plugin/index.ts:248) → 收所有三種

**Implication for Purdex**: Since Purdex's `event:` hook 走 `bus.subscribeAll()` fan-out, Purdex **可以收到所有 48 個 events**（包含 GlobalBus-only 的 `worktree.*` / `project.updated` / `workspace.*` 等）。但 catalog manifest 仍須 per-event 標註 publish mechanism（type-only / global-only / mixed）以 future-proof（若日後改用 typed `Bus.subscribe(def, cb)`，會錯過 GlobalBus-only 事件）。

### 3.3 Decision 3 — `session.idle`

**驗證結果**: 
- Definition: `session/status.ts:37` 帶 `// deprecated` (line 36)
- Publish: `session/status.ts:75` — fired only when `status.type === "idle"` inside `set()`，與 `session.status` 同一 code path（先 publish Status，再 publish Idle if idle）

**Rationale (preferred dualSubscribe)**:
- `session.idle` 顯式 deprecated 但仍 emit；典型 partial-stale

**Rationale (alternative — switch)**:
- 單訂閱、面向未來、無 dedup 邏輯

**User 決定點**: dualSubscribe 增加少量 plumbing 複雜度但提供 deprecation removal resilience；switch 簡單但失去韌性。**audit 默認推薦 dualSubscribe；plan §6 H6.4 (e) 兩種 decision 都符合 ship gate**。

## 7. Audit notes & uncertainty

### 7.1 高信心發現
- `chat.message` 是 strong hook，不是 Bus event（zero `BusEvent.define` + zero `bus.publish` for chat.message；1 strong-hook callsite at session/prompt.ts:1237）
- Purdex 端 `chat.message` 訂閱 ALREADY 為 strong hook（plugin_template.go:167）— 沒有 silently broken
- `permission.ask` 為 DEAD strong hook（zero `plugin.trigger("permission.ask")` callsites — 6 grep 變體 + 22 callsite full enumeration cross-check）
- `session.idle` 顯式 `// deprecated`（status.ts:36）但仍 emit（status.ts:75）
- `SessionStatus.Info` 三變體（idle / retry / busy）
- `question.asked` Bus event 活著（question/index.ts:172）+ 經 `bus.subscribeAll()` 可達 plugin (plugin/index.ts:244)

### 7.2 GlobalBus-only / SSE-only 發布機制
- 7 events 走 `GlobalBus.emit` only（`worktree.*` / `project.updated` / `workspace.restore` / `workspace.status` / `global.disposed` + partial `server.instance.disposed`）— typed `Bus.subscribe(def, cb)` 收不到，但 `subscribeAll()` 收得到
- 1 event (`server.connected`) 走 SSE-only（`Bus.publish` 不發）— SSE handshake artifact
- **Purdex 用 `bus.subscribeAll()` 都收得到** — 但 events.json 必標 `publishMechanism` 欄 future-proof

### 7.3 Subagent 推測的 false positive（已澄清）
- Subagent C 推測 Purdex `chat.message` "silently broken" — 實際 Purdex template 已正確用 strong hook key（plugin_template.go:167）
- 此誤判反映 reviewer 對 OpenCode hook 結構的 ambiguity — events.json schema strongHooks 條目的 `interface_present` / `trigger_callsite_present` / `callsite_files` / `adoptability` 4 欄（per plan v1.3 §2.2 AL1）正是預防此類誤判的設計

### 7.4 不確定 / out-of-scope
- `tool.execute.after` cancellation gap：TaskTool path interrupt 時不 fire after-hook（lines 630-649 in prompt.ts）；其他 tool path（custom + MCP）的 cancellation 行為未完整驗證；對 Purdex `SubagentStop` 影響：cancelled subagent 的 activeSubagents Map entry 不會清，需 periodic GC（**out of PR-4a-0 scope；建獨立 issue 追蹤**）
