## Decisions
- **D1 Modules (pure, injected deps).** `electron/presence/sampler.ts` (idle + lock state), `electron/presence/reporter.ts` (hosts, capabilities, send loop), `electron/presence/ipc.ts` (validation + handlers), wired in `main.ts`. Deps injected: `powerMonitor` subset (`getSystemIdleTime`, `getSystemIdleState`, `on`), `fetch`, monotonic `now()`, timers, prefs load/save, logger. Tests never import `electron`.
- **D2 Sampler (spec §5.2).** Subscribe to `lock-screen`, `unlock-screen`, `suspend`, `resume` first, then read the current state; every event and read bumps a sample revision and a read never overwrites a newer revision. `getSystemIdleTime()` every 5 s. Lock start on the monotonic clock; on start and on `resume` reconcile with `getSystemIdleState(60)` — `locked` with no known lock start → lock age unknown → `locked_ms: 60000`. `snapshot(at)` returns `{idleMs, locked, lockedMs}` aged to `at` (idle seconds × 1000 + time since that sample). "User came back" = sampled idle dropped by ≥ 5 s → emits `back`.
- **D3 Host list (spec §5.1).** IPC `presence:set-hosts` with `{rev: number, hosts: [{hostId, baseUrl, token}]}`; main keeps the copy with the highest `rev` (equal `rev` ignored), memory only (tokens never written to disk, never logged, never sent to a renderer). Validation: plain object; `rev` a safe non-negative integer; ≤ 64 hosts; `hostId` non-empty string ≤ 128; `baseUrl` parses with `http:`/`https:` scheme, no credentials, ≤ 512 chars; `token` null or string ≤ 4096; payload ≤ 256 KiB serialised; anything else → rejected (the handler returns `false`, logs the reason without values).
- **D4 Capabilities.** Main fetches `GET {baseUrl}/api/info` (Bearer token, 5 s deadline) at start, when the list changes (new / changed hosts only), after a failed send to that host, and every 10 min; a host is reported v2 only while its last `capabilities` array contains `push.presence.v2`. A failed probe retries after 20 s.
- **D5 Sending (spec §5.3).** Per v2 host: a send every 20 s from the first moment; forced on `back`, lock, unlock, resume, N change, host-list change, capability first seen, first success after a failure. Body `{client_id: "mac:<installId>", active, sessions: [], ttl_ms: 45000, v: 2, idle_ms, locked, locked_ms, away_after_ms}` built from `snapshot(now)` at send time; `active` = at the computer by this Mac's own rule (not locked and `idle_ms < away_after_ms`, or locked under 60 s) — informational, the daemon ignores v1 fields of a v2 entry (spec §4.1). One request in flight per host; reasons arriving meanwhile coalesce into one send of the latest state when it settles; every request has a 10 s deadline (abort → in-flight cleared → resend latest). 2xx → ok; 4xx → logged at most once a minute per host, the host stays v2 but is retried only on the next tick; 5xx / network → failed (capability re-probe + forced send on the next success).
- **D6 Prefs.** `AppPrefs` gains `presenceAwayMinutes` (one of 1/2/3/5/10/15/30/60, default 5; anything else → default) and `installId` (generated once with `crypto.randomUUID()` on first need and saved; an invalid stored value is replaced). IPC `presence:get-away-minutes` → number; `presence:set-away-minutes` validates the value is in the set, saves, forces a send, returns the saved value.
- **D7 Bridge.** Preload `presence: { setHosts(payload), getAwayMinutes(), setAwayMinutes(n) }`; SPA type: `presence?: {…}` with every method optional. PA-2a ships the bridge; nothing in the SPA calls it until PA-2b.
- **D8 Host rev (PA-2b).** `useHostStore` gains a persisted `hostsRev` integer, incremented by every action that changes `hosts` or `hostOrder` (add / remove / edit ip, port, token / reorder); part of `partialize`, so all windows rehydrate to the same value; alpha — no migration (absent → 0).
- **D9 Hand-over (PA-2b).** One hook mounted in `App.tsx` (per window): when `window.electronAPI?.presence?.setHosts` exists, send `{rev: hostsRev, hosts: [{hostId, baseUrl: getDaemonBase(host), token}]}` on mount and whenever `hostsRev` changes. Every window sends; main keeps the highest `rev` (D3), so a stale window cannot win.
- **D10 v1 reporter yields (PA-2b).** The probe keeps the whole capabilities list. When the bridge has `presence.setHosts` **and** the host lists `push.presence.v2`, the window's v1 reporter sends one final v1 `active:false` for that host (so a lingering v1 entry cannot feed the legacy rule) and then stops reporting to it; without the bridge, or for a host without v2, behaviour is unchanged (spec §5.4).
- **D11 Setting (PA-2b).** One row in Settings → **Desktop App** (`ElectronSection`; there is no Notifications section, and this section is already the bridge-gated place): 「離開電腦幾分鐘後推到手機」 select 1 / 2 / 3 / 5 / 10 / 15 / 30 / 60, description 「在電腦前（這台 Mac 有鍵盤或滑鼠動作、沒鎖螢幕）時不推到手機；鎖螢幕 1 分鐘後也會推。」 (zh-TW + en). Read through `getAwayMinutes`, written through `setAwayMinutes`; hidden when `presence.getAwayMinutes` is absent. Not in the notification store, not in Profile Sync (spec §5.5).

## PA-2a — Electron shell (D1–D7), ~650
1. `app-prefs.ts`: `presenceAwayMinutes`, `installId` (+ tests: defaults, invalid values, lazy id persisted once).
2. `presence/sampler.ts` + tests: 5 s idle sampling; lock / unlock / suspend / resume; already-locked start → `locked_ms` 60000; resume-still-locked; event-during-read race (an older read never overwrites); monotonic lock age; `back` on idle drop ≥ 5 s; `snapshot` aging.
3. `presence/reporter.ts` + tests: keeps sending with no window (no renderer dependency); highest `rev` wins, stale / equal ignored; capability gating (only `push.presence.v2` hosts; probe retry; re-probe after failure; 10 min refresh); 20 s cadence from the first moment; each forced reason; coalescing while in flight; a request that never settles → 10 s timeout → resend latest; first success after failure → forced send; 4xx log throttle; body fields exact (`v: 2`, ages current at send time, `client_id` `mac:<installId>`).
4. `presence/ipc.ts` + tests: the validation table (shape, scheme, credentials in URL, sizes, counts, rev types); tokens never appear in log output; set-away-minutes rejects values outside the set.
5. `main.ts` wiring (start at ready with real `powerMonitor` / `fetch`, stop on `before-quit`), preload `presence` group, SPA type (optional methods).
Merge gate: PA-1 deployed on both hosts. After merge: `pnpm run electron:build` on mlab, then the dev update on the Air (coordinated with 1f, who owns deploys).

## PA-2b — SPA (D8–D11), ~400
1. `hostsRev` in `useHostStore` (+ tests: each mutating action increments; persisted; two stores rehydrated from the same storage agree).
2. Hand-over hook (+ tests: no bridge → no call; bridge → call on mount and on rev change with `http://ip:port` base and token; unchanged rev → no call).
3. v1 reporter yields (+ tests: old shell / plain browser → v1 to every push host as today; bridge + mixed hosts → v1 only to hosts without v2, one final `active:false` to a v2 host, then nothing; a host gaining v2 later switches; losing v2 switches back).
4. Settings row (+ tests: hidden without the bridge; shows the stored value; change calls `setAwayMinutes` and shows the saved value; zh-TW / en strings).
Merge gate: PA-2a's shell is on the Air (dev update done) — otherwise feature detection keeps v1, which is safe but untested; full vitest + `tsc -b`.
