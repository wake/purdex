## 2. Design choices (for the reviewer)

- **A card stack replaces the single panel area on `journal.v1` hosts only.** `components/journal/CardStack.tsx` mounts beside `TeamPanelArea` in `App.tsx`; per active tab exactly one of them renders, by the host's journal support (below). Columns right-aligned under the title bar: `[team card + roadmap under it] [journal card] [tasks tab]` (spec §11; the roadmap alone on the left without a team).
- **The team card on a `journal.v1` host is open or closed, nothing else** (the approved prototype; spec item 4 「separate panels that never overlap」): it shows today's `TeamPanel` content at the card size; the `titlebar` / `line` / `max` modes and the `TeamTitleStrip` do not exist there. Its open state lives in the journal UI state (`teamOpen` per team key), never in `useTeamUiStore`, so older hosts keep their modes untouched.
- **Workbook view fully off on `journal.v1` hosts** (spec §12): the notebook buttons, `OwnTitleStrip`, `TeamTitleStrip`, `panelView()`'s workbook branches, the drill (`TeamPanel` ignores `teamDrill`; the row and ended-seat drill entries hidden; a persisted drill is ignored, not erased, so an older host still finds it), and the team row's workbook status line (目前狀況 is not shown). **Kept**: `workbook-loader` and `useRelayBrief` (they feed the relay brief, not the view).
- **Sticky support**: the CardStack / TeamPanelArea choice uses the host's last known `journal.v1` answer — a disconnect (support `unknown`) keeps the last answer, so a journal host never flashes back to the workbook view; a host never answered yet uses the old UI; re-point or removal forgets the sticky answer.
- **Data**: `useJournalStore` per host + unit (entries by month pages, pinned, open confirm count, tasks, roadmap, `person_name`, `project.remote_url`), loaded through `lib/journal/api.ts`. A **journal loader** resolves the active tab's unit (own `cc` session, or the team's lead for a team tab; a member's tab → its team via the daemon) and keeps that unit loaded **even when the journal card is closed**, so the 日誌 button can show its count. `journal.changed` marks the matching resources (`what`: entries / tasks / roadmap) stale; only the active unit re-reads (debounced); hidden units re-read when they become active. Entries sorted by (`at`, `id`) client-side too.
- **Remote member**: `409 {lead_host_id, lead_session_id}` (J-1e) → the SPA maps `lead_host_id` to a configured host (`HostConfig` by daemon host id); all four endpoints go to that host with `lead_session_id`, and the unit key is that host's; a lead host this App does not have shows 「日誌在 <host>，這台 App 沒有連到」.
- **View state outside components, per unit** (`lib/journal/view-memory.ts`): journal / roadmap / tasks open, the three widths (initialised from the last used widths in the persisted `useJournalUiStore`), filter, scroll position and pinned-to-bottom, the opened 待確認 detail. The narrow-window drop is **visibility only** (computed from the window width each render), never written back, so widening restores what was open.
- **Pins**: optimistic per entry with a mutation generation; an error reverts only if the entry still shows that generation's value; a server read that lands later wins.
- **The person's name** comes from the API (`person_name`, per host) and is highlighted (warning-text colour on a soft warning fill) wherever it appears in an actor or a text; absent → no highlight; never hard-coded.
- **Refs** link to `<project.remote_url>/issues/<n>` (GitHub redirects PR numbers) when the API gives a remote URL; otherwise plain text.
