# Phone push notifications (APNs) — plan

Spec: `docs/specs/2026-10-09-push-spec.md`. Four PRs (PU-1 … PU-4), in order; the iOS PR runs in parallel in
purdex-ios against spec §4/§6/§8.

Rules for every task:
- TDD: the failing test first, then the code. One commit per task. Mutation check before asking for release: break the
  rule each test guards, see it red, restore.
- Tests that touch tmux: `-L <label>` and `unset TMUX`, never a bare `kill-server`.
- mlab resources: only the affected packages (`go test -race ./internal/module/push/...` etc.); `make lint`; a full
  `go test ./...` only before merge with the slot from purdex-1f.
- Secrets: never print `config.env`, the `.p8`, a JWT or a full device token — not in tests, logs, PR text or
  messages. Tests use a key generated in the test (`ecdsa.GenerateKey(elliptic.P256(), rand.Reader)` → PKCS#8 PEM
  in `t.TempDir()`).
- Review per PR: codex R1 + R2 (attack → critic). Release by the lead.

## PU-1 daemon: module, config, store, devices API, conditional `push.v1`

1. **Config.** `internal/config`: `PushConfig{APNsDir string}` under `toml:"push"` / `json:"push"`, zero value =
   off, included in the deep copy. Test: absent section → off; `apns_dir = "~/x"` round-trips; copy is deep.
2. **Key loader.** New package `internal/push/apnskey`: `Load(dir string) (Key, error)` reads `config.env`
   (only `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_KEY_FILE`; `KEY=value` lines, `#` comments, optional quotes),
   resolves the key file inside `dir` (reject absolute paths elsewhere, `..`, and symlinks that leave the dir —
   compare after `filepath.EvalSymlinks` of both), parses PKCS#8 → `*ecdsa.PrivateKey` on P-256. `Key` has no
   `String`/`MarshalJSON` that could leak (add a `String()` that returns `apnskey(<key id>)`). Tests: happy path;
   missing key; missing file; wrong curve; RSA key; path escape by `..` and by symlink; comments/quotes; the error
   text never contains file content.
3. **Store.** `internal/module/push/store.go`: `push.db` in the data dir (pattern of `internal/module/hostconfig/store.go`),
   the table of spec §4.4, `Upsert`, `Delete`, `List`, `MarkSent`, `MarkError`. Tests with `:memory:`.
4. **Validation + wire types.** `internal/push/wire.go`: `DeviceRequest`, `Prefs`, `AgentPrefs`, `DeviceView`
   (masked token), `PresenceRequest` (PU-3 uses it). `Validate()` per spec §4.1 (token hex 64–200 → lowercased;
   bundle id exact; env / platform enums; rune caps; printable; locale fallback; tabs ≤ 500; body ≤ 64 KiB enforced by
   the handler with `http.MaxBytesReader`). Table tests for each rule; masking `ab12cd34…ef90`.
5. **Module + routes.** `internal/module/push`: `Name() "push"`, Init loads the key (Init error → module fails to
   init, logged without secrets), opens the store, loads the cache; routes `POST /api/push/devices`,
   `DELETE /api/push/devices/{token}`, `GET /api/push/devices`. Cache and DB written together under one mutex (DB
   first, cache after success). Handler tests: upsert twice → one row, fields replaced; delete idempotent 204; GET
   masks; 400 cases; 413 over 64 KiB.
6. **Registration + capability.** `cmd/pdx/main.go` `registerServeModules`: add the module only when
   `Cfg.Push.APNsDir != ""` (like `[nex]`). `internal/core/info_handler.go`: append `"push.v1"` after the static list
   when `c.Mounted("push")`; keep the static list untouched (comment: the one conditional capability). Tests: info
   without the module has no `push.v1`; with it mounted it does; the static list is unchanged.

## PU-2 daemon: APNs client, sender, approval trigger

1. **JWT.** `internal/push/apns/jwt.go`: `Signer{key, keyID, teamID, now}` → `Token()` returns the cached JWT while
   younger than 40 min, else signs a new one (ES256, header `{alg,kid}`, claims `{iss,iat}`; signature = r‖s, 32
   bytes each, base64url without padding). `Invalidate()`. Tests: verify the signature with the public key; reuse
   within 40 min; new token after 40 min (fake clock); invalidate forces a new one.
2. **Client.** `internal/push/apns/client.go`: `Send(ctx, env, token, headers, payload) Result` against a base URL per
   env (production / sandbox constants; tests inject an `httptest.NewUnstartedServer` with `EnableHTTP2 = true` +
   `StartTLS` and its client). Result classes per spec §7 (ok / remove device / retry with new JWT / retry later /
   permanent error) from status + APNs `reason` JSON. 10 s timeout. Tests: every class, the request headers
   (`authorization: bearer …`, topic, push type, priority, expiration, collapse id), HTTP/2 used (`r.ProtoMajor == 2`).
3. **Payload + strings.** `internal/push/content.go`: builders for the four triggers of spec §6 and the §5.3 body
   normaliser (Markdown markers, whitespace, 240-rune cut, title 120 runes) with zh-TW / en tables; size check
   ≤ 4096 bytes (if over, cut the body further). Tests: each trigger in both locales; normaliser cases (bold, code,
   headings, quotes, bullets, links, CJK cut at a rune boundary); size cap.
4. **Sender.** `internal/module/push/sender.go`: one goroutine, queue 256, `Enqueue(job)` non-blocking (drop +
   counter + rate-limited log). For each device the job selects: send; on ok `MarkSent`; on remove → store delete +
   cache; on JWT error → `Invalidate` + one retry; on retry-later → one retry after 2 s (fake sleeper in tests); else
   `MarkError` with the reason. Stops on module Stop (drains nothing; in-flight request cancelled). Tests with the fake
   APNs: each path; a full queue never blocks `Enqueue`; Stop returns.
5. **Team feed.** `internal/team`: `ApprovalEventsKey` + interface `ApprovalEvents{ SubscribeApprovals(fn func(op
   string, a Approval)) (unsubscribe func()) }`. `internal/module/team`: implement it as a hub like `turnEndHub`
   (per-subscriber bounded channel + goroutine, non-blocking publish, drops counted); publish from `Module.broadcast`
   after the host event (inside `eventMu` is allowed only because the publish is a non-blocking channel send; say so
   in the comment); register in the Registry at Init. Tests: opened and closed reach a subscriber; a stuck
   subscriber does not slow `broadcast` (time-bound test like T-3a1's); unsubscribe stops delivery.
6. **Approval trigger.** push module `Dependencies()` adds `team`; at Start it subscribes. On `opened`: kinds of spec
   §5.1 (hook_ask only when `terminal_only` is false); builds the job for every device; R6 check is a no-op until PU-3
   (leave the hook: a `presence` interface with an always-false fake). Tests: lead / self_relay / hook_ask pushed;
   hook_ask terminal_only, hook_permission, adopt, `closed` not pushed; an unattended auto-approval (only `closed`)
   not pushed.

Acceptance after PU-2 (lead + iOS, real device): lead request with unattended off pushes; with it on, none; an
AskUserQuestion in a mod session pushes and the tap lands on the question.

## PU-3 daemon: agent hub, gate, presence

1. **Agent notify hub.** `internal/module/agent/notify_hub.go` like `turn_end_hub.go`: `SubscribeNotify(fn func(NotifyEvent))`
   with `NotifyEvent{SessionCode, SessionName, SessionID, Event agentpkg.NormalizedEvent}`; publish wherever a live
   `hook` host event for a **tmux** session is emitted (find the emit slot after `publishTurnEnd` in `handler.go`,
   and the mod-stream emit path if it emits `hook` frames for tmux sessions), never for subscribe-time replays
   (`Snapshot`). Add `SubscribeNotify` to the narrow interface the push module gets from the Registry. Tests: a hook
   that is emitted publishes once; a 500 before the emit publishes nothing; replay not published; a stuck subscriber
   does not slow the handler.
2. **Presence.** `internal/module/push/presence.go`: in-memory map `client_id → {active, sessions set, expires}`,
   `PUT /api/push/presence` (validation per spec §5.4: client id ≤ 64, sessions ≤ 200, ttl 1000–60000 ms; 204),
   `Shows(sessionCode) bool` = some unexpired active entry has it. Tests: shows / expires (fake clock) / inactive does
   not count / a second PUT replaces the first.
3. **Gate.** `internal/module/push/gate.go`: pure function of (event, device prefs, presence, open hook_ask set,
   debounce state, now) per spec §5.2 rules 1–9; the debounce is the Mac's (trailing-edge sliding 60 s, 1000 keys,
   oldest evicted). Port the Mac's `shouldNotify` test cases into a Go table and add rows for 5 (tabs /
   notify_without_tab), 6 (presence), 8 (open hook_ask by tmux name and by session id).
4. **Open hook_ask set.** Kept from the approval feed (opened → add, closed → remove), keyed by origin tmux name and
   session id; rebuilt from `GET`-equivalent store read at Start (the team module's open rows) so a restart does not
   forget open questions. Tests: add / remove / restart rebuild.
5. **Agent trigger.** At Start subscribe to the notify hub; per event, per device, run the gate; build the agent
   payload (spec §6, collapse id `agent-<code>`); enqueue. Approval trigger now also applies R6 (origin session's
   code shown by a present Mac → skip; the origin's tmux name maps to a code via the sessions list). Tests: end to end
   with fake APNs: Stop in a tab → push; not in tabs → none; with `notify_without_tab` → push; presence → none;
   expired presence → push; waiting while a hook_ask is open → none.

Acceptance after PU-3 + PU-4 (real device): the agent rows of spec §10.

## PU-4 SPA: Mac presence reporter

1. **Activity tracker.** `spa/src/lib/presence/activity.ts`: last input time from `keydown`, `pointerdown`,
   `pointermove` (throttled), `wheel` on the window; `isActive(now)` = `document.hasFocus()` and input within 120 s.
   Tests with fake timers and dispatched events.
2. **Visible sessions per host.** A selector over the active tab's panes (every pane, as `isAgentVisibleInActiveTab`)
   → `Record<hostId, string[]>` of session codes. Tests: split tab, non-session panes ignored, no active tab → empty.
3. **Reporter.** `spa/src/hooks/usePushPresence.ts`, mounted once in `App.tsx`: for every connected host whose
   `/api/info` announced `push.v1`, PUT `/api/push/presence` with `{client_id: getClientId() + ':' + windowId,
   active, sessions, ttl_ms: 45000}` on change (debounced 300 ms) and every 20 s while active; one `active:false` when
   it stops being active; nothing to hosts without `push.v1`. Failures are ignored (next tick retries). Tests: sends on
   focus/tab switch; heartbeat; `active:false` once; skips hosts without the capability; per-host session lists.
4. Tab-hosted state checklist: not applicable (no tab-hosted component).
